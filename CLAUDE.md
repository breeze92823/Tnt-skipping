## Current state: empty base
This repo was a boat-racing game. All of it has been removed because Bowling Roll is a new theme. What is left is the base to build on: **the player, the ground, material/texture helpers, physics and the sky**, drawn by a small `main.js`. There is a HUD with the popup windows (see **Windows** below) and UI sounds, but no networking, no saves and no gameplay loop yet. The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, ground slab + colliders, player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, sea ripples, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Ground**: `world.js` `buildGround(scene)` (the pale cracked-sand slab with rounded edge and a shallow-water band, through `buildSlab`), `landColliders()` (the slab's convex hull + an invisible fence on every edge), `createWorld(scene)` (the clouds; `.setSea({ level, color } | null)` shows a world's sea, built on first use, `.update(dt, elapsed, focus)` scrolls the ripples and moves the water with the focus). The slab outline is `BEACH` in config; the new lego-style lobby will replace it.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` is an unused hook; `setMoods(sky)` swaps in a world's sky. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Lobby** (`src/lobby/`, layout + texts + palette in `LOBBY` in config): the lego hub from the owner's reference screenshots. `index.js` `buildLobby(scene, preset)` builds the parts every world shares (shop, eggs, lanes, booth, boards) into one group and each world's look (floor, shop step, scenery, portal, tower) into its own, merges all static meshes per material (`kit.bakeStatic`; groups marked `dynamic()` are merged on their own and keep moving) and wires the particle emitters (`fx.js`: fuse sparks, portal sparkles, glitch pixels, gold glitter, lane glints; counts scale with the preset). `floor.js` island, studded plaza, green patches with yellow trims, checker floors, north runway with dirt banks, fences + rim walls; `nature.js` voxel pines/broadleaf trees, palms, bushes, rocks, hay, floating islands with waterfalls, windmill, Coconut Cove; `tnt.js` TNT models + the shop (two rows of pads, Dragon TNT); `landmarks.js` Pirate Isles portal (swirl shader), Glitch Egg booth, eggs + lion showcase, leaderboards, giant TNT tower; `lanes.js` the 7 skill lanes (signs at the target end), red brick tutorial path, bouncing arrow; `paint.js` canvas painters (studs, TNT wraps, signs via `paintTextStack`); `kit.js` studded materials, metre-UV `legoBox`, `sign`, `localSolid`. Dev: `__game.setView('north'|'south'|'east'|'west')`.
- **Windows** (ported from Clap to Destroy's `ui.js` / `windows.js`, measured off the owner's 11 screenshots; `--u` = 1px at 1920x990, capped so each window's footprint `--fw` x `--fh` fits; on touch / portrait they fill the screen and the side tabs become a row): `ui.js` the shell (translucent frame, title over the top edge, corner icon, red X, `side` tabs outside the frame's left edge, `foot` under it; one open at a time; Esc / backdrop closes; `closeTopWindow` runs before Bloxity's menu on Esc), `windows.js` + `windows.css` the views: Rebirth (Before/After x SKILL, Level N / Level 20 bar, Rebirth, Skip Rebirth = premium price badge, toasts "coming soon"), Inventory tabs My TNT (tap an unowned card for its price, tap again to buy) / My Pets (detail card, lock, equip, delete, INDEX, Equip Best; with no pets the Common Egg's pets show as a preview) / My Eggs (Open = hatch overlay) / My Boosts (drink a potion), Pet Index (Normal / Golden / Diamond / Exclusive variants, every `PETS.indexStep` discovered = +`indexLuck`% luck, CLAIM / CLAIM ALL), Trails (x Wins), Playtime Rewards (session clock) and Daily Rewards (24 h, streak breaks after 48 h), and the egg panel (hold E at a lobby egg: pet tiles with live odds, Hatch 1 / 3 / 8 under the frame, hatches on the spot, Robux eggs toast "coming soon"; closes past `INTERACT.eggLeave`). `progress.js` is the state + rules (actions return a refusal message or nothing; `snapshot()` / `hydrate()` for a future save; progress lasts the page for now). `hud.js` / `hud.css` the menu tiles (Rebirth %, TNT, Pets, Trails, Gifts timer), the calendar button, SKILL / Wins / Rebirths and toasts (own layer over the windows). `icons.js` window SVGs (+ `public/ui/rebirth.png`), `pets.js` cube-pet portraits per `look` + variant recolours and the hatch overlay, `audio.js` synthesized UI sounds. Tunables in config: `REBIRTH`, `TNTS`, `PET_KINDS`, `PET_VARIANTS`, `EGGS`, `PETS`, `BOOSTS`, `TRAILS`, `PLAYTIME`, `DAILY`. SKILL multiplier = (1 + rebirths) x equipped pets' mults (summed) x the Skill potion; Wins x trail boost x the Wins potion x `REBIRTH.winsScale` per rebirth past `winsFrom` (the Rebirth window flags it from then on). `__game.progress` / `__game.windows` (dev) poke the state and open windows.
- **Worlds** (`worlds.js`, `WORLDS` + `WORLD_FADE` in config, `lobby/pirate.js`): a world is the same layout, lanes, eggs, shop, prices and zone Wins under another look. `WORLDS[0]` is TNT Island (what the rest of config describes); `pirate` overrides colours, sky, sea, tower and the 13 zones' names and props. Hold E at the portal (zone `portal` in main.js, from a spot `LOBBY.portal.useAt` m in front of it) to go; a world opens for good at its `skill` (Pirate Isles 400M, which takes rebirth 8 as Skill caps at 372M on rebirth 7) and rebirths never close it. `progress.js` holds the rules: `state.worlds` (unlocked ids) and `state.world` (where the player is), both saved. `worlds.js` `update()` sees `state.world` differ from what is on screen (the portal or a loaded save), closes the screen, swaps in place and opens it: never a reload, because a guest's progress lasts the page. A later world's look and zones are built on its first visit, with `setSolids(false)` (propkit.js), since all worlds share the first one's colliders; `treeRing` keeps trees on the solid trunks' spots. `RUN.zones` is the current world's list, so read it at use, never at load. Players in another world are not drawn (`world` in the loadout, remotePlayers.js). `lobby/pirate.js`: props, `buildPirateNature` and `pirateDress` (one entry per zone `props`). The sea sits at -2.4 so it stays below the crater's deepest step (`BLAST.levels`). A new world needs its `WORLDS` entry, a `dress` entry per new `props`, and its scenery branch in `lobby/index.js` `buildLook`. `__game.worlds` (dev).
- **The throw** (tunables `THROW_ZONE`, `RUN`, `BLAST`, `TUTORIAL_THROWS` in config): the yellow band across the start of the lane is the Throw Zone; a wall at its front edge (`floor.js`) stops anyone walking onto the lane. `thrower.js` (Bowling Roll's bowler.js, Throw Zone part) shows THROW on the band (HUD button, F, or a click while the cursor is grabbed), plays `throwAnim.js` through `animator.layer` and carries the equipped TNT (`tnt.js` `tntModel(id, use)`). `run.js`: phases idle -> fly -> fuse -> blast -> return; Skill sets the range (`progress.throwRange`: `reachBase` + `reachScale` x Skill^`reachPower`, 625 m at 760 Skill, the 9.7 km end of the lane at 100M), one big arc then shrinking skips (`planHops`), each skip pays the TNT's Skill with a rising pentatonic note; it stops, the fuse beeps down, it blows with slow motion, flash and camera kick, pays Skill per `blastSkillEvery` m and the zone's `wins`; chase camera blended over camera.js. `runScenery.js` builds the 12 zones past the lobby (`RUN.zones`, Coconut Cove to Starfall Moon; the lobby's runway is The Green; a new zone needs a `dress` entry named by its `props`), baked and streamed by distance, with at most `propsPerBank` props per side. `blast.js`: skip puffs and the explosion. The crater is a real hole: lane floors use `kit.js` `holed(mat)`, which discards fragments in a mask (`laneHole`), over a stepped pit built from the same cells; `reset()` restores the lane once the camera is back. One-shot particles are `lobby/fx.js` `burster` (the caller runs update, so a blast can run in slow motion). `fx.js` + `game.css` world popups, zone banner, +N WINS; `audio.js` the throw's synthesised sounds. Levels are flat: `REBIRTH.perLevel` Skill each, x `scale` per rebirth, Skill caps at the rebirth level. Pacing target: 100M Skill takes 2 h+ of play (about 2.4 h typical, 7 rebirths, first TNT by ~3 min), and Dragon TNT about 10.5 h (rebirth 8 needs 372M Skill, so `winsFrom` / `winsScale` only act after 100M). The balance is a chain, so re-check it when changing any of `REBIRTH.scale`, zone `wins`, TNT and egg prices, lane `req` or `blastSkillEvery`; each sign's text in `LOBBY.shop` / `LOBBY.eggs` repeats its price by hand. `__game.step(n, dt)` runs frames by hand, `__game.run` / `thrower` / `blast` (dev).
- **Server, saves, multiplayer** (`net.js`, `remotePlayers.js`, `pet3d.js`; backend contract in its CLAUDE.md): `net.js` joins room `world` (`NET` in config: `VITE_SERVER_URL`, `npm run dev` defaults to ws://localhost:2567, builds ask the Bloxity matchmaker), `initNet(progress)` hydrates `progress` from the server's `progress` message and sends `progress.snapshot()` as `saveProgress` when it changed (at most every `NET.saveEvery` s, plus on hide / close; playtime alone only every `NET.playtimeSaveEvery` s). **Nothing about progress is kept in the browser** (only a dev-mode id); guests are never saved. `onLeaderboard` feeds the lobby stand's four screens (`lobby.setLeaderboards`: Wins, Time Played, Best Throw, Skill). Presence: `sendPose` (10 Hz, only when it changed), `sendLoadout` (equipped TNT / trail / pets), `syncAvatar` (the Bloxity look JSON), `sendFx` (run.js `onFx`: throw / fly / skip / boom / end). `remotePlayers.js` draws everyone else: their avatar with Bloxity skin + proportions, the walk / run / jump animation from the relayed speed and `air`, the throw arm (`throwAnim.js`), name tag, their pets (`pet3d.js` cube critters that hop after the owner; also used for the local player), and their TNT flights, skip puffs and blasts (`blast.js` `remoteFuse` / `remoteBoom`: shockwave ring, flash, fireball, pixels, smoke, sparks, dust; no crater). Optimisations: nearest `NET.maxRemotes` (`maxRemotesTouch` on touch) only, nothing past `remoteFade` m, animation + pets only within `detailRange` m, no shadows, shared rig / geometry / materials, at most `flyBuffer` remote TNTs, throws further than `fxRange` m along the lane are not drawn. `__game.remotes` / `myPets` (dev).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, F (or THROW) throw on the yellow band, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
